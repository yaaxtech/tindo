# TinDo — Login real — plano incremental

> Aprovado pelo dono em 2026-07-31. Implementar em PRs pequenos e sequenciais.
> Mudanças de autenticação não atravessam a fronteira de um PR sem verificação e CI verde.

## Objetivo

Substituir o usuário fixo do MVP por Supabase Auth real no TinDo inteiro, preservando os dados
atuais de `falecomseucamarao@gmail.com` e preparando o isolamento necessário para o
compartilhamento do RoadMapMind.

## Decisões aprovadas

- Login por senha e por link mágico na mesma tela.
- Cadastro aberto, com confirmação obrigatória de e-mail.
- Cadastro pede nome, e-mail e senha; WhatsApp é opcional e serve somente para suporte.
- Link mágico não cria contas desconhecidas; novos usuários passam por `/cadastro`.
- Sessão persistente com renovação automática e logout explícito.
- Depois do login, voltar para a rota originalmente pedida; fallback `/docs`.
- Recuperação de senha entra no primeiro ciclo.
- `/configuracoes` ganha uma seção Conta para nome, WhatsApp, senha e logout.
- Landing e telas de auth ficam públicas. Páginas de produto e APIs de dados exigem sessão.
- Cloudflare Turnstile protege cadastro, link mágico e recuperação de senha.
- Compartilhamento e edição simultânea continuam em frentes posteriores e separadas.

## Arquitetura alvo

- Requisições do usuário usam o cliente Supabase da sessão e, portanto, exercitam RLS.
- A identidade é validada por claims assinadas; `getSession()` não é fonte de autorização.
- `service_role` fica restrito a automações autenticadas por segredo, nunca a requests normais.
- Rotas técnicas recebem um `usuario_id` explícito durante o processamento multiusuário.
- O parâmetro de retorno pós-login aceita apenas caminhos internos da aplicação.
- Respostas que carregam ou renovam sessão não podem ser cacheadas de forma compartilhada.

## Verificação obrigatória por PR

```bash
bun run typecheck
bun run lint
bun run test
```

Nos PRs que mudam comportamento de auth, somar teste local com dois usuários e smoke test do
fluxo afetado. O corte final exige um usuário temporário novo comprovando que não enxerga nenhum
dado do dono atual.
